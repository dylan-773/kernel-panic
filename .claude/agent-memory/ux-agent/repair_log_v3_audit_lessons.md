- **Concurrent `/kp-ui` cycles can race `pipeline/proposals/ux-agent.json` and `pipeline/BRIEF.md`; when that happens the coordinator redirects to a per-demo `ui-demos/<id>/SPEC.json`.** This happened on repair-log-v3: another session's DARKNET.LNK cycle overwrote `pipeline/BRIEF.md` mid-run, and a third session's writes clobbered `pipeline/proposals/ux-agent.json` between this agent's read and its write, losing the item entirely. The fix was NOT "write earlier" (see [[ux-agent-proposal-house-style]], which already covers that failure mode) but a different mechanism: the coordinator asked for output at an uncontended path (`ui-demos/<id>/SPEC.json`, envelope `{"agent","cycle","items"}`, no `brief` field) that it merges into the shared file itself in one pass at the end of the cycle. **Why:** multiple agent sessions can genuinely run in parallel against this repo now (evidenced by `inbox-v3`/`dadlog-v3` directories appearing mid-cycle); a single shared JSON file is not safe under that condition. **How to apply:** if a coordinator message says the shared proposals file doesn't hold this agent's prior work despite it having been written, do not assume authorship failure -- check for a redirect to a demo-scoped path before re-deriving anything, and re-emit already-completed reasoning verbatim into the new location rather than re-thinking it.

- **When the coordinator has already built the demo, the job shifts from "author a ui-spec" to "audit the build and describe it accurately, flagging disagreements."** This is a distinct mode from the usual "propose, then Orchestrator builds": read the shipped `index.html` line by line against `RULINGS.md` and the game source, trace CSS role-token usage class by class rather than trusting the file's own header comment (repair-log-v3's own header comment overclaimed `--r-note`'s reach by one class, `.rl-cname`, versus what the CSS actually did), and verify game-derived numbers by tracing them back to the actual source constants (`content/customers.ts`, `content/arc.ts`) rather than trusting a scenario object's inline comment math. Two real, substantive bugs were caught this way that a scan of the header comments alone would have missed: an internally-consistent-looking but externally-wrong tier/day pairing for a real customer (Bram Hollander computed at tier 5 on day 8, but his `tiers` are `[2,3]` and day 8's `jobTiers` cap at 4), and an entirely unhandled empty-state branch (`piece === null`, "no piece this ticket") that the code would throw on rather than render, since none of the four built scenarios ever exercises it.

- **To check a `clamp(floor, Ncqi, ceiling)` ratio claim without a live browser, compute the ACTUAL container width the `cqi` resolves against, not the clamp's ceiling.** A clamp's max value is only reached if `Ncqi` at the real container width exceeds it; for a narrow nested container (here, a bill cell at ~1/3 of a ~670px row after subtracting grid gaps and cell padding), `26cqi` of ~207px is ~54px, nowhere near a 78px ceiling that looks generous on paper. Do the arithmetic explicitly (subtract term border, `.term-body` padding, grid gaps, and the target element's own `container-type:inline-size` box before applying the coefficient) before asserting a hierarchy ratio holds or fails; this caught a real ~1.8-1.9x focal ratio against RULINGS law 2's reference figure of 2.2x that a glance at the CSS alone would have missed (the clamp's own ceiling, 78px against a 32px slab, would naively look like 2.4x). Flag findings like this with the worked arithmetic shown, not just the conclusion, since the agent cannot run the CDP harness itself (no Bash/browser tool access in this role) and the number should be treated as an estimate pending a real measurement.

- **A "compound multi-cell focal group" (several co-equal hero numerals sharing one visual weight class) is an accepted way to satisfy "one focal element," established by LOADOUT.CFG's SCAN/ATTACK/DEFEND trinity and reused here as THE BILL's three cells (CREDITED numeral, BILLED numeral, RECOVERED glyph).** Law 2 does not require a literal single number; it requires exactly one TIER of extreme scale that nothing else reaches, and a same-scale row of 2-3 related readouts (all bracketed as one unit, all built by the same helper function) reads as one focal group rather than several competing elements, as long as nothing else on the surface reaches that scale.
