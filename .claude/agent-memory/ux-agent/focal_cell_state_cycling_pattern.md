**Pattern:** when a surface is a flat stream with nothing that's obviously "the biggest thing" (a CLI log, a ticker, a status board), don't force one fixed value to extreme scale. Instead build ONE cell at extreme scale whose CONTENT changes across the surface's own real states, and give every state the IDENTICAL fixed footprint (a `min-height` sized to the tallest state's real content, RULINGS law 4's equal-footprint rule generalized from empty/filled slots to empty/filled STATES of one panel). For DARKNET.LNK v3 (`pipeline/proposals/ux-agent.json`, item `darknet-v3-instrument-panel`): PENDING (dial in progress) → OFFER (tonight's price, a hero numeral) → REVEAL (the landed piece, a hero glyph) → DEAD (the alarm, hero text), one cell, same box every time.

**Why:** law 2's hierarchy rule ("one focal element, 2x+ scale") assumes there's a candidate; a CLI/list surface's real content is many co-equal small facts, and picking just one of them to blow up (e.g. a single stat) either understates the surface's real focus or fights whatever the surface is actually telling the player at that moment. A state-cycling focal cell keeps the "one thing, extreme scale" law honest without freezing the surface's own narrative arc (an offer, then a payoff, then possibly an alarm) into a single static number.

**How to apply:** (1) enumerate the surface's own state machine first — not UI states, the underlying THING's states (channel dialing → channel open with an offer standing → a transaction just landed → channel dead) — before touching layout. (2) size the fixed footprint off the state with the MOST real content (here, REVEAL: an eyebrow + a hero glyph + 3 data rows), then backfill every thinner state's content to occupy that same row-block height with genuinely useful reused copy rather than blank padding where a natural reuse exists (OFFER borrowed the LIST card's own ITEM/SHAPE/STOCK rows verbatim to hit the same 3-row height as REVEAL's SHAPE/ARMS/GUARANTEE) — only accept true blank dead space for a state that's about to disappear anyway (NO CARRIER, window closes 900ms later), matching loadout-eva's own precedent that dead space "reads as instrument-panel spacing" when it's a deliberate, stated cost, not an oversight. (3) if one of the states is the surface's alarm state (RULINGS law 1), let the SAME cell also host the alarm when it applies — one "owner" for `--r-warn` can still be one element serving multiple logical roles across its state machine, it doesn't need a dedicated alarm-only element. (4) tie every state transition to an EXISTING sound at the same beat the underlying event already fires one, rather than inventing new sfx per visual state; state-cycling content is still just recoloring/repositioning an existing moment, not new interaction. See [[loadout-eva-fluid-window-techniques]] for the equal-footprint/cutting techniques this reuses, and [[ux-agent-proposal-house-style]] for how this got written up.

**Confirmed workable, not yet user-reviewed:** this is a first-round proposal (ux-2026-07-31-darknet-v3), not a validated pattern the user has signed off on — treat the "why" above as the reasoning to defend if it comes back with a review note, not as settled house law yet.
