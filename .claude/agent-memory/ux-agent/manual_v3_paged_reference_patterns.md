- **Law 8 step 5 ("paging or tabs in the narrow tier only") does not forbid a dedicated in-frame pager on a genuinely open-ended catalog at WIDE viewports.** That line governs reaching for pagination as a shortcut around a WIDE-tier space problem a real cut would solve; it does not govern content that cannot fit one page at ANY card density (MANUAL.TXT's 18-entry AUGMENTS catalog). The kpos-window-sizing-law memory already flagged MANUAL.TXT and DAD.LOG as the two windows with genuinely open-ended content; this cycle confirms the fix is DAD.LOG's own precedent restated ("paging is structural, not a fallback... it is the thing that makes the no-scrollbar law true for content it has never seen"), cited explicitly in the spec to preempt a reviewer reading law 8 step 5 as a blocker. **How to apply:** when a catalog-shaped page (an augment list, a bestiary, anything that grows over a save's lifetime) needs its own pager even at WIDE, cite this precedent by name rather than re-litigating law 8 step 5 from scratch.

- **DAD.LOG's measure-then-pack paginator (`paginate()`/`showPage()`) generalizes cleanly from prose BLOCKS to grid ROWS.** For a 3-column card grid, group items N-per-row in source-array order, measure each row's rendered height as the max of its N cards, then greedily pack whole rows (never partial rows) into a page against a fixed content-frame budget. This keeps the no-orphan-row guarantee DAD.LOG's own paginator gives prose, applied to a genuinely different content shape. Worth reaching for on any future card-grid-shaped catalog page (LEDGER, if it turns out row-shaped rather than table-shaped).

- **Two navigation levels on one paged reference surface must stay visually and lexically distinct, not merged.** MANUAL.TXT keeps three controls: the TAB STRIP (section nav, primary), the footer PAGE n/5 chip (a secondary book-flipping affordance over the same five sections, kept from the shipped component rather than removed for being "redundant" with the tabs), and a NEW in-frame SET n/N pager scoped only to the AUGMENTS tab's own card pages. Naming them different nouns (PAGE vs SET) matters: reusing "PAGE" for both would make "PAGE 2" ambiguous between "the KIT tab" and "the second card set of AUGMENTS." **How to apply:** whenever a surface needs pagination WITHIN a navigable section (not just between sections), mint a second noun for the inner pager rather than overloading the outer one, and keep the inner pager physically inside the content frame it paginates, never in the window's own footer.

- **A reference/help surface with no live risk state and no camera moment can leave BOTH `--r-warn` and `--r-aux` unowned at once**, not just one (NIGHT.SYS only had `--r-aux` unowned; MANUAL.TXT has neither role owned). This is a legitimate, decided-not-defaulted state per law 1's own text ("if a surface has no alarm state, it has no `--r-warn`"); state the reasoning explicitly (no strain/timer/failure state possible while the window is open; a manual page is not a live feed) rather than letting two blank rows in the roleTokens table look like an oversight.

- **Do not fix a downscaled-dither bug by re-cropping it correctly if the image is also a third reuse of an asset two other windows already show live.** MANUAL.TXT's shipped PATCHES tab forces a 304x304 dither down to 180x128 (a law 5 violation) using the same bench asset LOADOUT.CFG and DAD.LOG already display. The right fix here was CUT, not re-crop: re-cropping correctly would still leave a third instance of the same photo on the desktop, the exact "decorative duplication" NIGHT.SYS's own NOTES.md declined for a second instance. Filed the underlying downscale bug as a `suggestion` (`law5-downscale-audit`) pointing at LEDGER as the next place to check, rather than silently absorbing it into the cut.
